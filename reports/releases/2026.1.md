## What is new for customers?

### Billing contacts

The Owner and Billing admins can add extra email addresses that receive billing mail.

- Menu path: **Settings → Billing → Billing contacts**.
- Up to **5 extra addresses** per account.
- A billing contact receives the `invoice_ready` email for each invoice and the `payment_failed` email on day 0 and after each failed retry.
- A billing contact cannot log in, unless the same person is also a member. Being a billing contact gives no role and uses no seat.
- Typical use: the shared mailbox of an accounts-payable department.

### Invoice PDF redesign

Invoice PDFs under **Settings → Billing → Invoices** have a new layout.

- A summary block at the top shows the invoice ID (for example `INV-2026-004812`), the billing period, the plan, the number of seats and the total.
- Seats, storage packs and prorated amounts are separate lines. A prorated line shows the number of days it covers.
- The company name, billing address, VAT/GST ID and PO number come from **Settings → Billing → Billing details**.
- The invoice ID format did not change.

Invoices created before 2026-01-20 keep the old layout. They are still available and are kept for 7 years.

## What changed for admins and API users?

- Only roles with `billing.manage` (Owner, Billing admin) can add or remove billing contacts. Admins do not see the page, as before.
- Adding a sixth address is refused with `ERR_LIMIT_EXCEEDED` (HTTP 409).
- An address that is not a valid email address is refused with `ERR_VALIDATION` (HTTP 400).
- The `invoice_ready` notification now has two send steps: first the Owner and Billing admins, then the billing contacts.
- There are no new API endpoints and no new scopes in this release. The `billing:read` scope is unchanged.
- No new audit event was added. Changes to billing contacts are not in the audit log.

## Which fixes are included?

| Area | Fix |
|------|-----|
| Billing | The credit for removed seats is rounded to the nearest cent, half up, in the same way as charges for added seats. Before, a credit could differ by 1 cent. |
| Billing | The invoice list is sorted by invoice date, newest first, also for accounts with more than 100 invoices. |
| Notifications | The `storage_warning` email at 90% is sent once per crossing of the limit, not once per upload. |
| Accounts | A downgrade that is blocked by the workspace limit now names the limit in the message. |

No incident follow-ups shipped in this release.

## What do I need to do to upgrade or migrate?

Nothing is required.

- Existing accounts start with zero billing contacts. The Owner and Billing admins keep receiving all billing mail.
- Customers who forwarded invoice emails by hand can add the target address as a billing contact and remove the forward.
- Customers who read invoice PDFs with a script should check the script against the new layout. The invoice ID, the total and the currency appear on the first page in the summary block.
- The database change is additive: one new table for billing contacts. No existing data was changed.

## What is the rollback plan?

- **Billing contacts** are behind a feature flag. Turning the flag off hides the page and stops the second send step. Saved contacts stay in the database and return when the flag is turned on again.
- **Invoice PDF layout** has a switch between the old and the new renderer. Switching back affects invoices created after the switch only.
- **Full rollback**: deploy the last 2025 build again. Target time is 30 minutes per region. The new table is ignored by the old build, so no data rollback is needed.
- **Decision**: the release manager decides on a rollback together with the on-call engineer. `eu-central` is not deployed if `us-east` shows a problem on the first day.

No rollback was needed. The flag for billing contacts was removed from the code in 2026.3.
