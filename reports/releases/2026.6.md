## What is new for customers?

### Audit log filters

Owners and Admins on Pro and above can filter the audit log under **Settings → Audit log**. Before this release the page was one long list, newest first.

| Filter | Values |
|--------|--------|
| Event type | One or more of the recorded event types, for example `login.failed`, `member.removed`, `api_key.revoked` |
| Actor | A member, an API key, **Acme Cloud support** or **System** |
| Date range | Any range inside the plan's retention period |

The three filters can be combined. Example: all `api_key.revoked` events by one Admin in the last 90 days. The page opens on the last 30 days, and **Clear filters** returns to that view.

### CSV download

The filtered list can be downloaded as a CSV file with **Download CSV** under **Settings → Audit log**.

- The file has one row per event, with the columns `event_id`, `time_utc`, `actor`, `event`, `workspace_id` and `metadata`. Event IDs look like `evt_3G7H2K9M4P6Q`.
- The download contains all filtered events, not only the rows on screen.
- One file holds up to **50,000 events**. For more, narrow the date range and download in parts.

### 7-year retention on Enterprise

Enterprise accounts now keep audit events for **7 years**.

| Plan | Audit log retention |
|------|---------------------|
| Free, Starter | No audit log |
| Pro | 90 days |
| Business | 1 year |
| Enterprise | 7 years |

Before this release, Enterprise events were kept for 1 year, like Business.

## What changed for admins and API users?

- Viewing, filtering and downloading need the permission `audit.read`, which the Owner and Admins have. Billing admins, Members and Guests do not see the page.
- The audit log is append-only (ADR 0008). Filters and downloads only read it. Events are never edited or deleted before the retention period ends.
- The list of recorded events did not change. No new event type was added in this release.
- Each event still stores the actor, the account, the workspace (if any), the time in UTC and a small metadata object.
- The audit log has no REST API scope. The seven API key scopes are unchanged.
- An account that moves from Enterprise to a lower plan keeps events only for the lower plan's period from the day of the change.

## Which fixes are included?

Incident follow-ups for INC-2026-004:

| Fix | Team |
|-----|------|
| Exports running longer than 24 hours are marked `failed`. A `failed` export does not block a new one. The requester is told. | Accounts team |
| A `running` export whose lease has not been renewed for 5 minutes goes back to the queue, and another worker takes it. Before, only `queued` exports were handed out. | Accounts team |
| New runbook `docs/runbooks/stuck-export.md`. | Accounts team |
| 5 new unit tests and 3 new integration tests for the time limit and for a worker that stops in the middle of a job. | Accounts team |
| New alert `export-running-too-long`: the on-call engineer is paged when any export has been `running` for more than 6 hours. | Platform team |
| The admin console shows the worker and the last lease renewal of each export. The on-call engineer can **Requeue** a stuck export or **Mark failed**. Support agents cannot change an export's status. | Support Tools team |

The first and third rows are the follow-up listed in the index. The code change is in `src/acme_cloud/workspaces/export.py`.

The temporary measures from the incident ended on 2026-08-19, when the release reached all regions: waiting for running exports before a worker restart, and the daily manual check for old `running` exports.

Other fixes:

| Area | Fix |
|------|-----|
| Audit | Events for a removed member show the member's name at the time of the event, not "unknown user". |
| Audit | `login.failed` events for an email address that is not a member are no longer listed under a workspace. |
| Workspaces | The old synchronous export is switched off for all accounts. Its code is removed in 2026.7. |

## What are the known issues?

| Issue | Status |
|-------|--------|
| The 7-year retention applies to events that still existed on 2026-08-18. Enterprise events that were already deleted under the old 1-year rule cannot be restored. For an Enterprise account the oldest possible event is from 2025-08-18. | By design. |
| A large CSV download takes time to prepare. The page shows a progress message. | Faster in 2026.7, where rows are sent while they are read. |
| The CSV file writes the metadata object as JSON text in one column. Spreadsheet programs show it as one cell. | By design. |
| An export that reaches the 24-hour limit is not restarted automatically. The Owner or an Admin starts a new one under **Settings → Workspace → Export**. | By design. |

## What do I need to do to upgrade or migrate?

Nothing is required.

- **Enterprise accounts**: the longer retention applies automatically. There is no setting and no extra cost.
- **Pro and Business accounts**: filters and the CSV download appear under **Settings → Audit log**. Retention is unchanged at 90 days and 1 year.
- **Customers who copied the audit list by hand** for reviews can now use the CSV download.
- **Exports**: an export that was already in `running` at deploy time got its 24-hour limit counted from its real start time. No export was older than 24 hours at deploy, so none was marked `failed` by the release.
- **Export statuses** are unchanged: `queued`, `running`, `ready`, `expired`, `failed`. What is new is one more reason for `failed`.

## What is the rollback plan?

- **Audit log filters and CSV download** are behind a feature flag. Turning it off returns the page to the plain list. No data is touched.
- **7-year retention** is a retention setting per plan. It can be set back to 1 year for Enterprise, but the deletion job for Enterprise events stays paused for 30 days after such a change, so that no event is deleted by a rollback.
- **24-hour limit and lease recovery** have separate flags. If lease recovery misbehaves, it is turned off and the temporary measures from INC-2026-004 start again. The 24-hour limit stays on.
- **Full rollback**: deploy the 2026.5 build again. Target time is 30 minutes per region.
- **Decision**: the release manager decides together with the on-call engineer. `eu-central` and `ap-south` are not deployed if `us-east` shows a problem on the first day.

No rollback was needed.
