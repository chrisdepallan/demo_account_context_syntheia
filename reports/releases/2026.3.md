## What is new for customers?

### Passkeys as an MFA method

Every user can add a security key or a passkey as a second factor.

- Menu path: **Profile → Security**, then add the method "Security key or passkey".
- The method uses the FIDO2/WebAuthn standard. Hardware keys such as a YubiKey work, and so do passkeys stored on a phone or laptop.
- A user can have more than one method, for example a passkey and an authenticator app.
- After setup the screen shows **10 single-use backup codes**, as for the other methods.
- The MFA methods are now `totp`, `webauthn` and `sms`.

### SMS hidden for Admins and Owners

On Business and Enterprise accounts, Admins and Owners no longer see SMS codes as an option under **Profile → Security**.

- Reason: these roles can change security settings, members and, for the Owner, billing and ownership. SMS is the weakest of the three methods.
- Members and Guests on all plans still see SMS.
- Admins and Owners on Free, Starter and Pro still see SMS.

## What changed for admins and API users?

- A passkey satisfies the **Require MFA** policy (**Settings → Security → Require MFA**, Pro and above). The 7-day grace period from the user's next login is unchanged.
- **Reset MFA** under **Settings → Members** removes all methods of the member, including passkeys.
- Adding a passkey writes an `mfa.enrolled` event to the audit log. The event metadata names the method.
- The Owner's break-glass login under **Enforce SSO** accepts a passkey as the MFA step.
- Support cannot add or remove a single passkey. Support can only do a full MFA reset, and for the only Admin or the Owner this still takes up to 2 business days.
- The REST API is not affected. API keys do not use MFA.

## What do I need to do to upgrade or migrate?

For most users nothing is required.

**Admins and Owners on Business and Enterprise who use SMS**

- An existing SMS method was not removed. It keeps working at login.
- The option to add SMS is gone. If the method is removed or MFA is reset, SMS cannot be chosen again.
- These users see a banner under **Profile → Security** that asks them to add an authenticator app or a passkey.
- At release time 1,870 Admins and Owners on Business and Enterprise used SMS as their only method. By 2026-05-26 the number was 640.

**Accounts with Require MFA turned on**

- No change is needed. Users can meet the policy with any of the three methods that they can see.

**Billing**

- The dunning schedule is unchanged: day 0 `past_due`, retries on days 1, 3, 7 and 14, `read_only` on day 14, downgrade to Free on day 44.
- The only change is that a processor outage no longer counts as a failed attempt.

## What is the rollback plan?

- **Passkeys** are behind a feature flag. Turning it off hides the method. Passkeys that were already added stay stored but are not asked for at login; the user's other methods and backup codes still work. A user whose only method is a passkey would need an MFA reset, so the flag is the last choice after the first week.
- **SMS visibility** is a separate flag and can be turned off without touching passkeys.
- **Outage detection** has its own flag. Turning it off returns to the old behaviour, where every failure counts. The pause switch for the two jobs works with the flag on or off.
- **Full rollback**: deploy the 2026.2 build again. Target time is 30 minutes per region.
- **Decision**: the release manager decides together with the on-call engineer. `eu-central` is not deployed if `us-east` shows a problem on the first day.

No rollback was needed.
