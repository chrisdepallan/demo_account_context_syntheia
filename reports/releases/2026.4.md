Release report for Acme Cloud 2026.4. All data is fictional sample data.

This is the first release that includes `ap-south`. The region opened to customers on 2026-05-27 with the 2026.4 build as its first deploy. From this release on, every deploy goes to `us-east` first and to `eu-central` and `ap-south` one business day later.

## What is new for customers?

### `ap-south` region for Enterprise

Enterprise accounts can create workspaces in a third data region.

| Region code | Location | Plans |
|-------------|----------|-------|
| `us-east` | Virginia, USA | All plans (default) |
| `eu-central` | Frankfurt, Germany | Business and Enterprise |
| `ap-south` | Mumbai, India | Enterprise only |

- The region is chosen in the region picker when a workspace is created. It is fixed at creation and cannot be changed later.
- Files, projects and exports of a workspace in `ap-south` are stored in that region.
- An account can have workspaces in several regions.

### UPI payments for Indian accounts

Accounts with a billing address in India can pay with UPI.

- Menu path: **Settings → Billing → Payment method → Update**, then choose UPI.
- UPI is offered on all paid plans for Indian accounts, next to cards.
- PayPal is not offered in India. That did not change.
- A failed UPI payment is handled like a failed card payment: `past_due` on day 0, retries on days 1, 3, 7 and 14.

## What changed for admins and API users?

- Creating a workspace in `ap-south` on a plan below Enterprise is refused with `ERR_PLAN_REQUIRED` (HTTP 403).
- The API base URL is the same for all regions: `https://api.acme-cloud.example/v1`. Requests are routed by the workspace's region.
- API rate limits are per key and are the same in every region. Enterprise keys have 5,000 requests per minute.
- The SAML URLs are the same for all regions. The ACS URL stays `https://auth.acme-cloud.example/saml/acs/{workspace_id}`.
- A UPI payment method is stored like every other method: as an opaque processor token such as `pm_9XK2M4QH7T`. No UPI address is stored, logged or shown in full.
- Changing the payment method to UPI writes a `payment_method.updated` event to the audit log.
- The status page `https://status.acme-cloud.example` shows the three regions separately.

## What are the known issues?

| Issue | Status |
|-------|--------|
| An existing workspace cannot be moved to `ap-south`. | By design (ADR 0002). Export the data and create a new workspace in the new region. |
| The workspace export was still a synchronous download in this release and could time out for very large workspaces. This made region moves slow. | Fixed in 2026.5, where exports became queued jobs. |
| UPI cannot be used for annual plans paid by bank transfer or for Enterprise invoices with net-30 terms. Those keep their existing methods. | By design. |
| Regional configuration can differ between regions without a report. This allowed INC-2026-006 in `ap-south` in October 2026. | Fixed in 2026.8 with a daily report of differences. |

The last issue was not known at release time. It was added to this report after the incident.

## What do I need to do to upgrade or migrate?

Nothing is required for existing workspaces. They stay in their region.

**To use `ap-south`**

1. Check that the account is on Enterprise.
2. Create a new workspace and pick `ap-south` in the region picker.
3. To move existing data, export the old workspace under **Settings → Workspace → Export** and import it into the new one. The export link is valid for 7 days.
4. SSO is set up per workspace. Add the SAML connection again for the new workspace under **Settings → Security → SSO**.
5. API keys belong to a workspace. Create new keys for the new workspace under **Settings → API keys**.

**To use UPI**

1. Check that the billing address under **Settings → Billing → Billing details** is in India.
2. Choose UPI under **Settings → Billing → Payment method → Update** and approve the request in the UPI app.

## What is the rollback plan?

- **`ap-south`** can be closed for new workspaces with a flag in the region picker. Workspaces that already exist in the region keep running; a region with customer data is never rolled back.
- **UPI** is behind a feature flag. Turning it off hides the option. Accounts that already pay with UPI keep their token and are charged as normal.
- **Clock drift alert** is not rolled back; an alert cannot harm customers. The new login message can be switched back to the old text with a flag.
- **Full rollback**: deploy the 2026.3 build again in `us-east` and `eu-central`. Target time is 30 minutes per region. `ap-south` has no earlier build and would be put into maintenance until a fixed build is ready.
- **Decision**: the release manager decides together with the on-call engineer. `eu-central` and `ap-south` are not deployed if `us-east` shows a problem on the first day.

No rollback was needed.
