# Test Run Report: Release 2026.7 (2026-09-22)

This report covers the test run at the code freeze for release 2026.7. The release shipped on 2026-09-29. It made webhooks generally available and introduced the `Acme-Signature` header. It also carried the follow-up to INC-2026-005: automatic replica promotion, tested every quarter. All data is fictional sample data.

## Which automated tests failed, and why?

### Failure 1: retries were spread over more than 24 hours

- Test: `tests/unit/notifications/test_webhook_retry.py::test_sixth_retry_is_24_hours_after_first_failure`
- Expected: a failed delivery is retried 6 times over 24 hours. The retries happen 1 minute, 5 minutes, 30 minutes, 2 hours, 8 hours and 24 hours after the first failed attempt.
- What happened: the sixth retry was scheduled 34 hours 36 minutes after the first failure.
- Cause: each wait was counted from the previous attempt, not from the first failure, so the waits added up (1 minute + 5 minutes + 30 minutes + 2 hours + 8 hours + 24 hours).
- Fix: the scheduler stores the time of the first failure and counts every retry from it.

### Failure 2: the signature was not computed over the bytes that were sent

- Test: `tests/unit/notifications/test_webhook_signature.py::test_signature_covers_raw_body`
- Expected: the `Acme-Signature` header is an HMAC-SHA256 of the exact request body.
- What happened: a receiver that checked the signature against the body it received got a mismatch for payloads with non-ASCII characters, such as a workspace name with an accent.
- Cause: the body was signed, then encoded a second time before sending, which changed the bytes.
- Fix: the body is encoded once, and the same bytes are signed and sent.

### Failure 3: a Pro account could add a sixth endpoint

- Test: `tests/unit/notifications/test_webhook_endpoints.py::test_endpoint_limit_per_plan`
- Expected: Starter 2 endpoints, Pro 5, Business 20, Enterprise 50; Free has none. One more than the limit fails with `ERR_LIMIT_EXCEEDED`.
- What happened: the limit check allowed one endpoint too many on every plan.
- Cause: the check compared with "greater than" before adding the new endpoint, instead of "greater than or equal".
- Fix: comparison corrected. A test for Free accounts (`ERR_PLAN_REQUIRED`) was added.

### Failure 4: the replica was not promoted on staging

- Test: `tests/integration/test_region_failover.py::test_replica_is_promoted_without_an_operator`
- Expected: when the primary database of a region stops, the replica becomes primary without human action.
- What happened: in `staging-eu-central` the replica was not promoted. The test passed in `staging-us-east` and `staging-ap-south`.
- Cause: configuration. Automatic promotion had been switched on in production after INC-2026-005 but not in the `staging-eu-central` config file.
- Fix: the Platform team moved the setting into the shared base config, so a region cannot miss it.

The four fixes were merged on 2026-09-23. A full second run on 2026-09-24 (commit `b62e4c1` plus four fix commits) gave 483 passed, 0 failed and 6 skipped.

## Which tests were skipped?

- `billing`: 1 UPI test (needs the processor's UPI sandbox).
- `auth`: 2 tests that need a real identity provider; they run weekly.
- Integration: 2 bank-transfer tests, and 1 new test that sends a webhook to a real external receiver. The external receiver test runs nightly against a receiver on staging, not at the freeze.

Six tests were skipped, one more than in the 2026.6 run.

## Did the external penetration test affect this run?

Yes. The external penetration test ran from 2026-09-14 to 2026-09-25, partly on this release candidate. Its one high-severity finding concerned which addresses a webhook endpoint URL may point to. The fix was merged on 2026-09-18, before the freeze, with 4 new tests in `tests/unit/notifications/test_webhook_endpoints.py`. All four passed in this run. Details are in `reports/security/2026-penetration-test-summary.md`.

## Was the release approved?

Not at first. The decision on 2026-09-22 was **No-go**, because three failures were in the headline feature and one was in the failover follow-up for a P1 incident.

The decision on 2026-09-24 was **Go**.

- Approved by: the release manager, the Platform team lead and the Identity team lead.
- Condition: the Platform team measures webhook delivery in production for four weeks after release. Done; see `reports/performance/2026-10-webhook-delivery.md`.

## What should the next run improve?

1. Settings that must be the same in every region belong in the shared base config. The Platform team started a review of per-region settings. The review was still open when INC-2026-006 (a key cache setting in `ap-south`) was found on 2026-10-15.
2. Write limit tests for the exact limit and for one above it, on every plan.
3. Do not test for behaviour the product does not promise, such as event order.
