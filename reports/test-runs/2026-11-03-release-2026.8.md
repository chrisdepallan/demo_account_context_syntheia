This report covers the test run at the code freeze for release 2026.8. The release shipped on 2026-11-10. Ownership transfer now needs acceptance within 7 days, and OIDC was added as an SSO protocol next to SAML 2.0. The release also carried the follow-up to INC-2026-006: the API key cache lifetime is fixed at 60 seconds in code, not in config. All data is fictional sample data.

## Which automated test failed, and why?

### Failure 1: a transfer request expired one day early

- Test: `tests/unit/accounts/test_ownership_transfer.py::test_request_can_be_accepted_on_day_7`
- What the test does: the Owner requests a transfer to an Admin. The Admin accepts 6 days and 23 hours later. The rule is that the new Owner must accept within 7 days, so the acceptance must succeed.
- What happened: the acceptance failed with `ERR_CONFLICT`, because the request was already marked as expired.
- Cause: the expiry was calculated in whole calendar days, counting the day of the request as day 1. A request made late in the evening lost most of its first day.
- Fix: the Accounts team changed the expiry to exactly 7 × 24 hours after the request time in UTC. Two more tests were added: acceptance one second before expiry succeeds, and acceptance one second after expiry fails.
- Customer impact if shipped: a new Owner who waited until the last day would have seen "request expired" and the Owner would have had to start again.

The fix was merged on 2026-11-04. The repeat run passed with 519 passed, 0 failed and 6 skipped. (The total rose to 525 with the two added tests; the freeze count of 523 is the number used in other reports.)

## How was the INC-2026-006 follow-up tested?

INC-2026-006 was found on 2026-10-15. Revoked API keys kept working for up to 15 minutes in `ap-south`, instead of the 60 seconds stated in the key rules. The key cache lifetime was set to 900 seconds in that region's config. The follow-up has 5 new tests in `api_keys` and 1 new integration test.

- The cache lifetime is a constant of 60 seconds and cannot be changed by a config file or an environment variable.
- A revoked key is refused with `ERR_UNAUTHENTICATED` no later than 60 seconds after revocation.
- A rotated key still works for 24 hours, and then stops.
- The integration test `tests/integration/test_key_revocation.py::test_revoked_key_is_refused_within_60_seconds_in_every_region` runs against all three staging regions.

All six tests passed. Manual case `TC-KEY-021` repeated the check by hand in `staging-ap-south`: a key was revoked in **Settings → API keys**, and requests with it were refused after 38 seconds.

## Were the penetration test fixes checked?

Yes. Four findings of the September 2026 external penetration test were fixed in this release. Each fix has at least one automated test, and all passed in this run:

- the key revocation delay (tracked as INC-2026-006, see above);
- the staff session idle timeout in the admin console;
- the login lockout counter shared across auth nodes (5 failed attempts within 15 minutes lock for 15 minutes, whichever node receives them);
- formula characters escaped in the audit log CSV download.

The external testers confirmed the fixes in a retest on 2026-11-17. See `reports/security/2026-penetration-test-summary.md`.
