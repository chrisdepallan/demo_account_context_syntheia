## Which automated tests failed, and why?

### Failure 1: a second export returned the wrong error code

- Test: `tests/unit/workspaces/test_export_queue.py::test_second_export_returns_conflict`
- Expected: when an export is already `queued` or `running` for a workspace, a second request fails with `ERR_CONFLICT` (HTTP 409).
- What happened: the request failed with `ERR_VALIDATION` (HTTP 400).
- Cause: the check for a running export sat inside the input validator, so it raised the validator's error.
- Fix: the Accounts team moved the check into the export service, which raises `ERR_CONFLICT`.

### Failure 2: the export-ready email went to every Admin

- Test: `tests/unit/notifications/test_export_ready_email.py::test_export_ready_goes_to_requester_only`
- Expected: `export_ready` is sent only to the person who requested the export.
- What happened: the Owner and all Admins of the workspace received it.
- Cause: the new job stored the workspace ID but not the requester's user ID, so the email fell back to everyone with `workspace.export` permission.
- Fix: the job now stores the requester (for example `usr_2B6N8R4V`) and the email uses it. The download link stays valid for 7 days.

### Failure 3: the large-export integration test timed out

- Test: `tests/integration/test_export_flow.py::test_large_workspace_export_reaches_ready`
- Expected: a test workspace with 5 GB of files moves through `queued`, `running` and `ready`.
- What happened: the test was stopped by the test runner after 300 seconds while the export was still `running`.
- Cause: a problem in the test, not in the product. The fake storage backend paused in real time for each file, so 5 GB of small files took longer than the runner's 300-second limit.
- Fix: the fake storage now uses the fake clock, and the test finishes in 4 seconds.

This third failure pointed at a real gap. The test was stopped by the test runner. Nothing in the product would have stopped the export. The run notes record: "an export has no upper time limit; if a worker dies, the job may stay `running`". The gap was accepted for this release (see the conditions below). It was the root cause of INC-2026-004 on 2026-07-22.

All three fixes were merged by 2026-07-02. The repeat run passed with 423 passed, 0 failed and 5 skipped.

## Which tests were skipped?

- `billing`: 1 UPI test. The processor sandbox for UPI was not reachable from the CI runner. UPI is covered by manual case `TC-BILL-027`.
- `auth`: 2 tests that need a real identity provider for SAML metadata refresh. They run weekly, not at each freeze.
- Integration: 2 bank-transfer tests (ACH and SEPA), covered by `TC-BILL-019` and `TC-BILL-020`.

- `TC-WS-009` (export status is shown while the job runs): **Settings → Workspace → Export** showed "Running" for a job that was still `queued`. The label was corrected so that `queued` and `running` are shown separately.
- `TC-WS-012` (expired link): after 7 days the page still showed a **Download** button, which led to an error page. The button is now replaced by the text "Expired" and an option to start a new export.

Both cases passed on 2026-07-03.

## Was the release approved?

Yes. The decision was **Go with conditions**.

- Decision date: 2026-07-03.
- Approved by: the release manager, the Accounts team lead and the Platform on-call engineer.
- Condition 1: the Platform team runs an export benchmark in the week after release, with sizes up to 500 GB. Done on 2026-07-13 to 2026-07-15 (`reports/performance/2026-07-export-benchmark.md`).
- Condition 2: an upper time limit for exports is added in release 2026.6. Done: since 2026.6, an export that runs longer than 24 hours is marked `failed`.

## What was learned later?

INC-2026-004 happened on 2026-07-22, 15 days after the release. Workspace exports stayed in `running` for 9 hours 40 minutes because an export worker lost its job lease and nothing timed the job out. The freeze run had named this gap but had no test for it, because the missing behaviour did not exist yet. Two changes to the test process followed:

1. A gap that is accepted at a freeze now gets a ticket with an owner and a target release before the decision is signed.
2. New background jobs must have a "worker dies in the middle" test before the freeze.
